=====================================================================
 PI SSH SETUP  -  air-01
 Last updated: 2026-11-04
=====================================================================

Connect a laptop to the Pi over a direct ethernet cable and SSH in,
so you can work from the laptop instead of the Pi's monitor.

ADDRESSES
---------
  Pi (air-01)      eth0                192.168.50.2/24   user: penn  
  Laptop           wired/USB adapter   192.168.50.1/24   gateway: blank
  Pi hotspot       wlan0               10.42.0.1         (backup route)

Nothing on the cable hands out addresses automatically, so both ends
are set by hand. 


=====================================================================
 PART 1 - ON THE PI  (Pi's own terminal: monitor + keyboard)
=====================================================================

1) Make sure SSH is running. The status should say "active (running)".

     sudo systemctl enable --now ssh
     sudo systemctl status ssh

2) Set the ethernet address PERMANENTLY (once per Pi; survives reboot).

     sudo nmcli con modify "Wired connection 1" ipv4.method manual ipv4.addresses 192.168.50.2/24
     sudo nmcli con up "Wired connection 1"

3) QUICK FIX if step 2 isn't done yet (lost on reboot).

     sudo nmcli device disconnect eth0
     sudo ip addr flush dev eth0
     sudo ip addr add 192.168.50.2/24 dev eth0
     sudo ip link set eth0 up

4) CHECK before connecting. Look for LOWER_UP and exactly ONE address:
   inet 192.168.50.2/24

     ip -4 addr show eth0

   If a wrong address is also listed, remove it:

     sudo ip addr del <wrong-address>/24 dev eth0


=====================================================================
 PART 2 - ON THE LAPTOP
=====================================================================

Plug the ethernet cable from the Pi into the laptop (USB ethernet
adapter is fine). Then give the laptop's WIRED adapter 192.168.50.1/24.

--- WINDOWS (PowerShell -> right-click -> "Run as administrator") ---

1) Find the wired adapter's name. Its Status must be "Up".

     Get-NetAdapter

2) Set the address (replace "Ethernet" with the name from step 1):

     New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.50.1 -PrefixLength 24

3) Check it:

     ipconfig

   You should see "IPv4 Address: 192.168.50.1" under that adapter.
   If you see 169.254.x.x instead, the setting didn't apply - redo step 2.

   GUI alternative: Settings -> Network & internet -> Ethernet ->
   IP assignment -> Edit -> Manual -> IPv4 on
   IP 192.168.50.1, mask 255.255.255.0, gateway blank.

--- LINUX LAPTOP ---

USB adapters have names like enx00e04c3d8b48. Find yours:

     ip -br link

Then (replace <adapter> with that name):

     sudo ip addr flush dev <adapter>
     sudo ip addr add 192.168.50.1/24 dev <adapter>
     sudo ip link set <adapter> up

--- MAC ---

System Settings -> Network -> ethernet/USB adapter -> Details ->
TCP/IP -> Configure IPv4: Manually
IP 192.168.50.1, subnet mask 255.255.255.0, router blank.


=====================================================================
 PART 3 - CONNECT  (run on the LAPTOP not on the Pi)
=====================================================================

     ping 192.168.50.2
     ssh penn@192.168.50.2

First time: type "yes" at the fingerprint prompt, then the penn password.

Optional - VS Code: install the "Remote - SSH" extension, connect to
penn@192.168.50.2, and open Pi folders as if they were local.

Optional - short name. Add this to ~/.ssh/config on the laptop
(Windows: C:\Users\<you>\.ssh\config), then just run: ssh air01

     Host air01
         HostName 192.168.50.2
         User penn


=====================================================================
 TROUBLESHOOTING
=====================================================================

SYMPTOM: nmcli device status shows eth0 "unmanaged"
  FIX:   Part 1 step 2, or: sudo nmcli device set eth0 managed yes

SYMPTOM: eth0 stuck on "connecting (getting IP configuration)"
  CAUSE: waiting for an automatic address that nothing provides
  FIX:   Part 1 step 2 (manual address)

SYMPTOM: ip link show eth0 says NO-CARRIER or DOWN
  CAUSE: no live device on the other end of the cable
  FIX:   reseat/swap cable or adapter; the Pi's port lights should blink

SYMPTOM: ping times out
  CAUSE: laptop address missing / on the wrong adapter, or a stray
         address on the Pi
  FIX:   laptop: ipconfig     Pi: ip -4 addr show eth0
         each side should show exactly one 192.168.50.x address

SYMPTOM: ping fails but everything looks right
  CAUSE: Windows Firewall blocks ping replies
  FIX:   try ssh anyway

SYMPTOM: Permission denied (publickey)
  CAUSE: password login disabled on the Pi
  FIX:   sudo nano /etc/ssh/sshd_config.d/50-cloud-init.conf
         set:  PasswordAuthentication yes
         then: sudo systemctl restart ssh

SYMPTOM: address gone after a reboot
  CAUSE: set with "ip addr add", which isn't saved
  FIX:   Part 1 step 2

SYMPTOM: Device "..." does not exist
  CAUSE: typo (eht0) or an adapter name from another machine
  FIX:   use eth0 on the Pi; enx... names only exist on a Linux laptop

COMMON TYPOS FROM FIRST SETUP
  systemctrl  -> systemctl
  ncmli       -> nmcli
  "dev dev"   -> dev
  Running laptop commands on the Pi (laptop commands go on the laptop!)

LAST RESORT - HOTSPOT
  On the Pi:      nmcli dev wifi show-password   (shows Wi-Fi name + password)
  On the laptop:  join that Wi-Fi, then  ssh penn@10.42.0.1
  (Laptop loses internet while on the hotspot.)
